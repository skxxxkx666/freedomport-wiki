wiki 视觉再升级方案（待执行） ​

状态：已确认方案，暂缓执行。目标 —— 脱离 VitePress 默认模板观感，做出克制、有母题、细节一致的高级审美（参照 Stripe / Linear / Vercel 文档站）。 原则：减法 + 一个贯穿母题 + 细节的极致一致，绝不堆装饰（emoji 已是反面教训）。

现状判断 ​

现在不难看，但一眼能认出是 VitePress——默认三栏布局、默认 hero（放大 logo + 一团光晕）、默认六宫格 feature 卡。模板痕迹集中在这些默认件上。

统领性母题：航线 ​

呼应品牌纸飞机与「自由港」之名。用一条极细的曲线航迹作为视觉线索，出现在 hero 背景、章节之间的分隔，克制到几乎无意识。这是让全站「像一个作品」而非「一套模板」的关键，也是唯一允许张扬的地方。

高杠杆改动（效果最明显） ​

1. Hero 重做 ​

放弃默认「放大 logo」，改成有构图的画面：

  • 左侧标题用更讲究的字号 / 字重 / 字距层次
  • 右侧不是孤零零的图标，而是「航线母题 + 品牌图」组成的安静构图
  • 第一印象决定「这站有没有设计」

2. 教程截图统一呈现（杠杆最大，手册主体） ​

现在截图是裸图直接贴。改成：

  • 桌面截图套一层极简窗口边框（三个圆点 + 圆角标题栏）
  • 手机截图统一圆角 + 柔和投影 + 居中限宽
  • 全站几十张图立刻像「一套」，专业感飙升
  • 实现：自定义 markdown 容器或图片包裹组件（纯 CSS）

3. 底色分层 + 字体 ​

  • 默认「性冷淡纯白」换成 Cloud Dancer 暖白的微妙分层（hero / 内容 / 卡片三层）
  • 标题用一款有个性的字体（几何无衬线或思源宋体），正文保持系统字体保证加载速度
  • 中文 web font 按需子集化，只给标题，控制体积

细节层（锦上添花） ​

  • 步骤竖向时间线：数字徽章 + 连接线，替代普通 H3 标题，教程有「流程感」
  • feature 卡重排，拉大留白，hover 微交互
  • 导航栏滚动玻璃态
  • 章节滚动入场动效（克制，受 prefers-reduced-motion 约束）

成本与风险 ​

  • 母题曲线、图片外框：纯 CSS，零依赖
  • 自定义字体：中文 web font 增加加载体积，需按需子集化
  • 整套铺开需一轮设计 + 逐页验证

执行建议 ​

不一次性全站开工。先做首页 + 一个教程页的完整视觉预览（母题航线 + hero 重做 + 截图外框 + 底色字体），截图确认后再铺到全站。改动范围可控。

待用户确认的开放项 ​

  • 是否引入自定义字体（体积 vs 质感）
  • 航线母题的强度（是否觉得多余）
  • 截图外框对手机截图的处理方式（套设备壳 vs 仅圆角阴影）
